## 2. 问题一：端口不一致

### 错误现场

**前端** `lantu_web/src/api/index.ts` 第 4 行：

```ts
const api = axios.create({
  baseURL: 'http://localhost:8080/api',  // ❌ 写死 8080
  timeout: 10000,
  headers: { 'Content-Type': 'application/json' },
})
```

**后端** `lantu_web_java/src/main/resources/application.yml` 第 2 行：

```yaml
server:
  port: 8080  # 原本写的是 8080
```

用户实际将后端运行在 **8081** 端口，前端请求全部发往 8080，导致连接失败。

### 修复方式

**后端** — 修改 `application.yml`：

```yaml
server:
  port: 8081  # ✅ 改为 8081
```

**前端** — 修改 `src/api/index.ts`，baseURL 改为相对路径 `/api`，依赖 Vite proxy 转发：

```ts
const api = axios.create({
  baseURL: '/api',  // ✅ 改为相对路径，由 Vite proxy 转发
  timeout: 10000,
  headers: { 'Content-Type': 'application/json' },
})
```

### 如何还原

```bash
# 后端 application.yml
git checkout -- lantu_web_java/src/main/resources/application.yml

# 前端 api/index.ts
git checkout -- lantu_web/src/api/index.ts
```

或者手动修改：

- `application.yml`：`port: 8081` → `port: 8080`
- `api/index.ts`：`baseURL: '/api'` → `baseURL: 'http://localhost:8080/api'`

## 3. 问题二：缺少 Vite 代理配置

### 错误现场

`lantu_web/vite.config.ts`：

```ts
export default defineConfig({
  plugins: [vue()],
  // ❌ 缺少 server.proxy 配置
})
```

前端 `localhost:5173` 直连后端 `localhost:8081`，触发浏览器的 CORS 限制。虽然后端有 `CorsFilter`（配置了 `allowCredentials(true)` 与 `allowedOriginPatterns("*")`），但在本地开发中仍不可靠。

### 修复方式

在 `vite.config.ts` 中添加代理：

```ts
export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8081',  // ✅ 代理到后端
        changeOrigin: true,
      },
    },
  },
})
```

效果：前端请求 `http://localhost:5173/api/auth/login` → Vite 自动转发 → `http://localhost:8081/api/auth/login`

### 如何还原

```bash
git checkout -- lantu_web/vite.config.ts
```

或者手动删除 `server.proxy` 块。

## 5. 问题四：密码明文存储

### 错误现场

`lantu_web_java/.../service/UserService.java` 第 26-31 行（注册）：

```java
User user = new User(
    request.getAccount(),
    request.getPassword(),  // ❌ 直接存储明文
    request.getNickname(),
    request.getPhone()
);
```

第 43-45 行（登录）：

```java
if (!user.getPassword().equals(request.getPassword())) {  // ❌ 明文对比
    throw new RuntimeException("账号或密码错误");
}
```

数据库中 `password` 字段直接存储用户原始密码，存在严重安全风险。

### 修复方式

**1. pom.xml 新增依赖：**

```xml
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-crypto</artifactId>
</dependency>
```

**2. 新增 `config/SecurityConfig.java`：**

```java
@Configuration
public class SecurityConfig {
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

**3. 修改 `UserService.java`：**

- 注册时：`passwordEncoder.encode(request.getPassword())` 加密后存储
- 登录时：`passwordEncoder.matches(request.getPassword(), user.getPassword())` 验证

**注意：** 修复前已注册的用户密码是明文，修复后这些用户无法登录（BCrypt 无法匹配明文哈希）。需要重新注册或手动更新数据库密码为 BCrypt 哈希值。

### 如何还原

```bash
# 删除 SecurityConfig
rm lantu_web_java/src/main/java/com/example/lantu_web_java/config/SecurityConfig.java

# 回退 UserService
git checkout -- lantu_web_java/src/main/java/com/example/lantu_web_java/service/UserService.java

# 回退 pom.xml
git checkout -- lantu_web_java/pom.xml
```

## 6. 问题五：登录认证缺少 JWT Token

### 错误现场

`AuthController.java` 登录/注册返回数据中只包含 `id`、`account`、`nickname`，没有 token：

```java
Map<String, Object> data = Map.of(
    "id", user.getId(),
    "account", user.getAccount(),
    "nickname", user.getNickname() != null ? user.getNickname() : ""
    // ❌ 缺少 token
);
```

后续需要鉴权的接口无法识别请求方身份。

### 修复方式

**1. pom.xml 新增依赖：**

```xml
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.5</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.5</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.5</version>
    <scope>runtime</scope>
</dependency>
```

**2. 新增 `util/JwtUtil.java`：**

- `generateToken(userId, account)` — 生成 JWT（24 小时有效期，HMAC-SHA256 签名）
- `getUserIdFromToken(token)` — 从 token 解析用户 ID
- `validateToken(token)` — 校验 token 是否有效

**3. 修改 `AuthController.java`：**

登录/注册成功时调用 `JwtUtil.generateToken()` 生成 token 并放入响应 data 中。

**4. 修改前端 `LoginPage.vue`：**

```ts
localStorage.setItem('user', JSON.stringify(res.data.data))
localStorage.setItem('token', res.data.data.token)  // ✅ 保存 token
```

**5. 修改前端 `RegisterPage.vue`：**

注册成功后跳转到登录页（文案微调）。

### 关于 token 的使用

后续需要鉴权的接口，前端可在请求头中携带 token：

```ts
// axios 请求拦截器示例
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})
```

后端可通过 `JwtUtil.getUserIdFromToken()` 解析 token 获取用户身份。

### 如何还原

```bash
# 删除 JwtUtil
rm lantu_web_java/src/main/java/com/example/lantu_web_java/util/JwtUtil.java

# 回退 AuthController
git checkout -- lantu_web_java/src/main/java/com/example/lantu_web_java/controller/AuthController.java

# 回退前端页面
git checkout -- lantu_web/src/views/LoginPage.vue
git checkout -- lantu_web/src/views/RegisterPage.vue

# 回退 pom.xml（去掉 jjwt 依赖）
git checkout -- lantu_web_java/pom.xml
```

### ⚠️ 已知注意事项

1. **Java 环境要求**：后端需要 **JDK 17+**（Spring Boot 3.2 的要求）。如用 Java 8 会编译失败。
2. **已有用户数据**：修复前注册的用户密码是明文存储，BCrypt 加密后这些用户无法登录。需要重新注册。
3. **数据库配置**：`application.yml` 中的 MySQL 连接配置（`localhost:3306/lantu_web`）需确保数据库已创建。
